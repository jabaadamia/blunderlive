# Finished Game Streams

Core processes finished games asynchronously through Redis Streams.

## `games.finished`

Produced by the game service when a game reaches a terminal state. The event is
idempotent by `game_id`; core may receive the same game more than once.

Required fields:

- `game_id`: UUID
- `white_player_id`: UUID
- `black_player_id`: UUID
- `result`: one of `1-0`, `0-1`, `1/2-1/2`
- `termination`: one of the `Game.Termination` values
- `rated`: `true` or `false`
- `rating_category`: rating category for rated games; omit or blank for casual games
- `initial_time_ms`: integer
- `increment_ms`: integer
- `started_at`: ISO-8601 datetime
- `ended_at`: ISO-8601 datetime
- `move_count`: integer
- `fen_final`: final FEN
- `pgn`: final PGN generated by the game service

## `games.processed`

Produced by core after the game is persisted and ratings are applied. Consumers
must be idempotent by `game_id`; the event can be emitted more than once if the
worker crashes after publishing but before acknowledging the source event.

Fields include:

- `game_id`
- `white_player_id`
- `black_player_id`
- `result`
- `termination`
- `rated`
- `rating_category` when rated
- `rating_applied_at`
- `white_rating_before`, `white_rating_after`, `white_rating_delta` when rated
- `black_rating_before`, `black_rating_after`, `black_rating_delta` when rated

## `games.failed`

Produced by core when a `games.finished` event is permanently invalid, such as
missing required fields, invalid enum values, invalid boolean values, or unknown
users. Transient infrastructure/database errors are left pending for retry.
